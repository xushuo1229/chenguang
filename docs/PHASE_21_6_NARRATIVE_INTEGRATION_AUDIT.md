# 第21.6阶段 · 成长叙事集成审计

审计日期：2026-09-15
范围：仅限决策审计。
没有修改业务代码、店铺架构、同步协议、后端架构、内存模型、分析、增长智能或 AI 上下文。

# 1. 当前状态

* *结果：叙事价值有效，但用户接触仍然过窄。**

当前链是：


```text
CGStore
→ Analytics
→ GrowthIntelligence
→ GrowthTimeline.buildTimeline()
→ GrowthTimeline.buildNarrative()
→ Stats
```

叙事层目前将时间线事件转换为如下阶段：


```text
起点
→ 稳定尝试
→ 稳定节奏
→ 投入积累
→ 阶段成果
→ 当前方向
```

它输出：


```js
{
  version: "1.0",
  today: "YYYY-MM-DD",
  dataSufficient: true,
  summary: "成长阶段：起点 → 稳定尝试 → ...。",
  currentStage: {
    id: "stage:...",
    label: "...",
    meaning: "...",
    evidenceIds: [],
    confidence: 0-1
  },
  stages: []
}
```

该实现仅在运行时有效。它不会被持久化、同步、写入内存或注入到 AI 上下文中。

当前强度：

1. 该预测是有界的。
2. 阶段含义使用固定文案。
3. 证据编号仍然可追踪。
4. 置信度保持在`0-1`范围内。
5. 它不会生成不存在的历史日期。

当前弱点：

叙述仅在统计中可见。统计是完整长期档案的正确归宿，但访问频率通常低于工作台。因此，叙述尚未强化日常动力。

# 2. 产品价值审计

## 2.1 长期记忆

* *状态：需要改进。**

叙述可以提高记忆保留，因为它将孤立的记录转化为可见的进展。然而，它目前仅存在于统计中。每天打开工作台的用户可能看不到它。

这个产品想法很好，但曝光不完整。

## 2.2 用户成就

* *状态：良好。**

这个叙述帮助用户理解目标、连续记录、专注总计和课程完成情况并不是孤立的数字。它们成为更长故事中的阶段。

这直接支持所期望的感觉：


```text
原来我已经走了这么远。
```

## 2.3 日常使用动机

* *状态：需要改进。**

工作台目前专注于今天的状态、每日反馈和下一步行动。这是正确的，但它尚未显示连续性。

一个轻微的当前阶段暗示可以将今天的行动与更长的情节联系起来：


```text
当前成长阶段：稳定尝试
```

这应该很小。它不应该取代今天的反馈。

## 2.4 人工智能个性化

* *状态：尚未准备好进行上下文扩展。**

AI 已经接收分析、增长智能、目标、记忆、报告和每日反馈。它可以在不使用新的上下文字段的情况下解释增长。

现在添加完整的叙述会有重复的风险并增加上下文大小。更有用的下一步是工作台暴露。

## 2.5 产品总体价值

* *总体：需要改进。**

叙事概念得到了验证，但激活尚未完成。统计证明了模型;工作台将激活每日感知。

# 3. 工作台审计

## 3.1 当前工作台职责

工作台当前拥有：


```text
Today’s status
Daily Feedback
Today’s actions
```

《增长简报》已经显示了今天的变化、重点、关注点和推荐的行动。这一界限是正确的。

## 3.2 工作台是否应显示 `currentStage`？

* *推荐：B — 仅轻微暗示。**

工作台应显示一句话：


```text
当前成长阶段：稳定尝试
```

它不应该显示完整的叙述。

## 3.3 为什么不选择选项A——没有整合

选项A将保留当前边界，但它会使叙事被使用不足。

用户的每日入口点不会从长期进展中受益。这削弱了第21.5阶段的留存价值。

## 3.4 为什么不选择选项 C — 完整叙述

选项C太重了。

工作台不应成为历史档案页面。展示所有阶段、证据和含义将会：

1. 与每日反馈竞争。
2. 增加认知负荷。
3. 重复统计数据。
4. 将工作台从操作中转移。

## 3.5 推荐的工作台展示

在现有的增长简报内或附近添加一条有界线：


```text
当前成长阶段：稳定尝试
```

可选的支持句：


```text
你开始把记录变成一种节奏。
```

规则：

1. 仅显示`currentStage`。
2. 不要渲染所有阶段。
3. 不要渲染证据ID。
4. 不要渲染时间表列表。
5. 如果`dataSufficient`为假或`currentStage`为空，隐藏提示。
6. 使用`textContent`。
7. 将提示保留在现有的增长简报中，而不是作为新的仪表板卡片。

## 3.6 数据重用要求

未来工作台的集成不得不必要地重新计算增长智能或分析。

它应消耗现有快照和已导出的增长简报状态。如果时间线需要 `personalBest` 或 `courseSummary`，应从当前快照中重用这些内容，并传递一次到投影中。

工作台集成不应在每次渲染时多次调用时间轴。

# 4. AI 审计

## 4.1 当前的人工智能输入

AI 上下文已经包括：


```text
overview
trends
daily
todos
courses
goals
growth
growthState
memory
coach
report
dailyFeedback
```

AI教练已经消耗：

1. 成长优势。
2. 成长风险。
3. 目标建议。
4. 已确认的记忆。
5. 每日反馈。
6. 成长评分及数据充分性。

## 4.2 AI现在需要`ctx.growthNarrative`吗？

* *推荐：否。**

人工智能已经可以解释现有领域的增长。

例如：

| 叙事问题 | 现有的人工智能输入 |
| --- | --- |
| “我最近稳定吗？” | `growthState.consistencyState` |
| “我有进步吗？” | `growth.trends`, `growthState.importantChanges` |
| “我完成了什么？” | `goals`, `courses`, 成长报告 |
| “下一步做什么？” | `growthState.recommendedFocus`, `actionProposals`, 每日反馈 |
| “我有哪些长期规律？” | 已确认的记忆 |

人工智能目前不需要专门的`growthNarrative`字段来回答这些问题。

## 4.3 连贯性风险

一个可能的问题是 Stats 使用固定的阶段标签，而 AI 可能使用它自己的语言。现在这是可以接受的，因为尚未向用户承诺 AI 知道确切的阶段标签。

如果以后产品希望由 AI 回答：


```text
我现在在哪个成长阶段？
```

然后可以添加一个紧凑的仅运行时字段。

## 4.4 未来人工智能的情境形态

如果人工智能整合变得必要，它应该是紧凑的：


```js
ctx.growthNarrative = {
  currentStage: {
    id: "stage:building",
    label: "稳定尝试",
    meaning: "你开始把记录变成一种节奏。"
  },
  summary: "成长阶段：起点 → 稳定尝试。"
};
```

它必须是仅运行时的。

它不得包含：


```text
stages[]
evidenceIds[]
confidence
version
today
raw user content
Memory content
```

除非后续阶段证明那些领域是必要的。

## 4.5 如果后来添加的修剪顺序

如果稍后添加 `ctx.growthNarrative`，它应被视为派生呈现数据，而非核心事实。

推荐修剪顺序：

1. 移除 `summary`。
2. 移除 `currentStage.meaning`。
3. 移除整个 `growthNarrative`。

核心分析事实、目标和主动行动背景应比叙述性存续更久。

# 5. 上下文 成本

一个只读的合成投影基准产生了：

| 项目 | 结果 |
| --- | --- |
| 时间轴节点 | 8 |
| 叙事阶段 | 5 |
| 完整叙事 JSON | 大约 953 个字符 |
| 精简 `currentStage + summary` JSON | 大约 105 个字符 |

预计情境影响：

| 设计 | 预计成本 |
| --- | --- |
| 完整叙述 | 大约 250-400 个词 |
| 简明叙述 | 大约 40-90 个词 |

完整的叙述不值得添加到AI上下文中。它重复了AI已经接收到的数据。

紧凑版本在技术上便宜，但仍应等到有真正的人工智能使用案例，例如用户反复询问时：


```text
我现在在哪个阶段？
```

不要仅为了与界面对称而添加上下文。

# 6. 内存边界

* *结果：叙述不是记忆。**

叙述是从时间线生成的系统解释。

记忆是不同的：


```text
Candidate Memory
→ User confirmation
→ Confirmed Memory
→ AI reads as long-term fact or possible trend
```

叙述绝不应写入：


```text
user.memory
CGStore
Sync payload
Backend database
```

原因：

1. 叙事阶段是衍生的解读。
2. 它们不是用户确认的事实。
3. 它们没有与内存相同的生命周期。
4. 它们不需要用户确认。
5. 将它们写入记忆会模糊解释与证据之间的界限。

如果产品以后希望用户将某个阶段保存为个人里程碑，那必须是一个单独的用户确认操作，并且需要单独的架构讨论。

# 7. UX 建议

## 统计

* *状态：正确。**

统计部门应继续拥有完整的长期档案。

推荐内容：


```text
成长轨迹
成长阶段摘要
Timeline nodes
```

这已经与产品边界对齐。

## 工作台

* *状态：应该添加轻微提示。**

工作台应只显示：


```text
当前成长阶段：当前阶段名称
```

这将今天的操作与更长的进程连接起来，而不会将工作台变成历史页面。

## AI

* *状态：目前上下文未改变。**

人工智能应继续使用现有的上下文进行解释。

它不应该显示完整的叙述。它应该回答个人问题，并将成长状态与下一步行动连接起来。

推荐的人工智能语言：


```text
根据你的记录，最近连续执行正在变得更稳定。
数据显示你的专注投入在增加。
可以先完成一个小目标，把这个节奏保持下去。
```

禁止的人工智能语言：


```text
你已经成为自律的人。
我已经完全了解你。
你一定会成功。
```

# 8. 安全审查

## 8.1 过度推断

当前的叙述文本大多是安全的，因为它使用了有限的舞台语言。

允许：


```text
数据显示你正在形成更稳定节奏。
你开始把记录变成一种节奏。
投入已经转化为阶段性结果。
```

禁止：


```text
你已经成为自律的人。
你的习惯已经彻底养成。
你一定会持续进步。
```

未来的整合必须保持这个边界。

## 8.2 编造的完成日期

当数据模型未提供 `completedAt` 时，时间轴会正确地避免使用它。

当前输出使用：


```text
asOf
```

这可以防止系统编造一个历史日期。

工作台和人工智能整合必须继续遵守此规则。

## 8.3 敏感内容

叙述使用固定标签和现有的时间线ID。它不应引入：


```text
Goal titles
Course names
Book names
Todo text
Chat content
Prompt content
Authentication fields
```

未来的 AI 上下文也应保持基于计数和阶段，而非基于原始内容。

## 8.4 自动内存

叙事不应将自己提升为记忆。

正确的边界：


```text
Narrative → UI only
Memory → Candidate + User confirmation + CGStore
```

# 9. 性能审查

针对当前投影生成的只读综合基准测试:

|操作 |1000分 |
| --- | --- |
| `buildTimeline()` | 关于 `5.83ms` |
| `buildNarrative()` | 关于 `4.29ms` |

每次调用的大致费用：


```text
buildTimeline: about 0.006ms
buildNarrative: about 0.004ms
```

对于用户界面来说，这是可以忽略的。

下一阶段的表现规则：

1. 重用现有快照。
2. 重用已派生的增长智能状态。
3. 不要对同一工作台渲染调用 Analytics 两次。
4. 不要对同一工作台渲染调用 GrowthIntelligence 两次。
5. 每次渲染构建一次时间线和叙事。
6. 不要添加新的缓存层。
7. 不要在叙事层中扫描原始的 365 天记录。

叙事层本身很便宜，因为它只对现有的有界时间线投影进行分组。

# 10. 最终建议

# 推荐的下一阶段

* *A. 第21.7阶段 工作台集成**

## Why

叙事本身已经具有技术价值，但曝光不足。工作台是日常的入口点。轻微的当前阶段提示可以在不增加上下文成本或改变架构的情况下提高动力。

## 价值

1. 将今天的行动与长期发展联系起来。
2. 改善每日的感知进展。
3. 在不增加新功能的情况下强化记忆。
4. 使用已经安全的运行时投影。

## 风险

如果实施保持在界限内，则较低。

主要风险：

1. 工作台变得过于历史化。
2. 重复分析计算。
3. 过度宣称养成习惯。

这些可以通过只显示一句话来控制。

## 实施范围

阶段 21.7 应仅包括：

1. 工作台增长简报集成。
2. 将 `currentStage.label` 显示为一个轻微的提示。
3. 如果 `currentStage.meaning` 仍然视觉上较小，则可选择仅显示 `currentStage.meaning`。
4. 当数据不足时隐藏提示。
5. 重用现有快照和增长简报状态。
6. 添加单元测试和页面测试。

第21.7阶段不应包括：


```text
AI Context expansion
Memory expansion
Store changes
Sync changes
Backend changes
Full Narrative in Workbench
New dashboard card
New persistent fields
```

AI上下文集成应推迟，直到实际使用显示用户期望AI回答确切的阶段性问题。
