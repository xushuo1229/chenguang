# 3. 架构合规

通过。

- 提取是课程知识的能力，而不是代理。
- 没有添加规划器、学生知识状态、自适应规划、人工智能导师、自治行动或多代理代码。

- 课程空间仍然是持久性和源边界。
- 候选项、证据和知识节点仍然是不同的层。

# 4. 候选边界

通过。

正常的提取路径仅调用 `insertCandidate` 和 `insertEvidence`（`backend/src/services/knowledgeExtractionService.js:151-184`）。它不会创建 KnowledgeNode。KnowledgeNode 的创建仅存在于用户发起的审查路径中的 `backend/src/services/knowledgeExtractionService.js:314-330`，该节点存储 `source_candidate_id`。

# 5. 提取管道

通过，但有发现。

该流程验证已拥有的课程，加载权威文档，记录版本/哈希，运行可注入提供者，在持久化之前验证所有输出，然后创建候选项/证据。提供者失败会映射到安全的作业失败代码。

持久化序列不是事务性的（F-003）。

# 6. 数据模型

通过。

`course_space_extraction_jobs` 和 `course_space_knowledge_candidates` 包括所有权、文档/版本、提供者/模型/提示身份、限制状态字段，以及候选原始/已审阅字段。附加的 `source_candidate_id` 和 `candidate_id` 列保持可追溯性。

# 7. 证据可追溯性

结构上通过；中等质量差距仍然存在。

每个候选者都有携带 `document_id`、`candidate_id`、`locator`、`quote` 和文档版本的证据。证据最初是未关联的，并会更新为已接受的节点 ID。

然而，该服务并未验证AI提供的摘录/定位符是否真实出现在或对应于源文档（F-004）。人工审核可以缓解但不能消除这一可追溯性弱点。

# 8. 自信

有界范围通过；仍存在中等验证差距。

需要有限的数字置信度，并受限于 `0 <= confidence <= 1` (`knowledgeExtractionService.js:131-133`)。它随后被确定性地映射到低/中/高。

`Number()` 强制转换将被遗弃的/空的/空字符串值视为零，而不是拒绝缺失的非数字置信度 (F-005)。

# 9. 审查 / 验证

生命周期意图通过；测试覆盖不完整。

只有待审候选者可以被审核。接受会生成一个节点；拒绝会使用`status='rejected'`保留候选者。原始的 AI 标题/内容仍保存在数据库中。

拒绝和 HTTP 路由授权行为缺乏直接测试 (F-007)。

# 10. 接受 / 拒绝

接受和拒绝都存在于 API 层。拒绝不会删除候选项。

Accept 不是并发安全的：两个请求都可能将候选项读取为待处理状态，都插入一个节点，并都关联证据。`source_candidate_id` 上没有事务、条件状态声明或唯一约束。这是 F-001。

# 11. 文档版本管理

通过。

作业存储 `document_id`、`document_version` 和 SHA-256 `content_hash`。候选项/证据继承相同的版本。历史候选项仍然可以追踪到已处理的版本，并且不会被后续提取重写。

# 12. 幂等性

通过。

键 `userId + documentId + documentVersion + contentHash + provider + model + promptVersion` 返回一个已存在的排队/正在运行/已完成的作业。`reextract` 允许一个新作业，同时历史作业保持完整。后台测试 `is idempotent for the same document version and content` 验证提供者调用次数。

# 13. 提供者边界

通过。

提供者包装器使用现有的兼容 OpenAI 的适配器注册表，以 JSON 数据发送文档内容，要求有界 JSON 输出，设置 `maxTokens`，并安全地处理失败。业务逻辑负责持久化。测试注入一个虚拟提供者。

# 14. API

路线布线和错误安全通过。

所有提取路由均经过认证;写入使用写限制器。输入有界并经过验证。响应暴露提供者/模型/提示符身份，但不透露秘密或栈痕迹。

路由级的集成覆盖率比服务级覆盖率薄（F-007）。

# 15. 授权

通过。

课程、文档、工作、候选人和证据查询包括 `user_id` 所有权检查。服务测试验证跨用户的课程/文档/候选人隔离。未发现跨课程的附件路径。

# 16. 安全

通过。

- 提供者密钥不会发送给客户端。
- 提供者内部信息不会在 API 错误中暴露。
- AI 输出在持久化之前会进行模式/边界检查。
- 前端使用 `textContent`，而不是 HTML 插值。
- AI 不能修改业务数据或绕过审查。

# 17. 边界性

对于一个新路径失败。

阳性对照：

- 提取输入限制为20,000个字符；
- 每个职位限制为10个候选人；
- 标题/内容/证据长度有上限；
- 职位/候选人列表使用默认/最大页面大小。

# 23. 发现

## F-001 — 并发接受可能会复制 KnowledgeNode

- 严重性：高
- 证据：`backend/src/services/knowledgeExtractionService.js:301-331`；`backend/src/db/knowledgeExtractionModel.js:110-135`；没有事务或唯一的`source_candidate_id`。
- 影响：两个并发的接受请求可能为同一个候选创建两个节点，并破坏一候选一节点的不变量。
- 建议：使用事务加条件待处理状态声明，或在`source_candidate_id`上添加唯一约束，并在物化之前验证行数。

## F-002 — 所需的审核用户界面功能缺失

- 严重性：高
- 证据：`js/courseSpaceExtractionUI.js:99-141`；`js/courseSpaceExtractionService.js:9-28`；真实浏览器结果显示没有定位器/版本或编辑控件。
- 影响：用户无法在审查工作区检查证据/版本或编辑候选项，这违反了第25阶段的最低用户界面契约。
- 建议：通过证据 API 渲染证据/文档版本，并在接受前添加有限的编辑输入。

## F-003 — 多步持久化不是原子级的

- 严重程度：中等
- 证据：候选/证据循环在`knowledgeExtractionService.js:151-184`;节点/证据/状态序列在`knowledgeExtractionService.js:314-330`;无交易包装。
- 影响：数据库故障可能导致部分候选人/证据或节点被链接，但候选状态未被接受。
- 建议：在SQLite事务中封装作业输出持久性和接受实现。

## F-004 — 证据摘录未经来源验证

- 严重性：中等
- 证据：AI 证据仅在 `knowledgeExtractionService.js:137-147` 处需要且长度有限，然后在第 171-180 行保存。
- 影响：AI 可能生成一个看似可信但伪造的引用/定位器；证据在名称上可追踪，但不一定有来源支持。
- 建议：要求摘录与文档内容匹配/规范化，或者对未经验证的证据进行标记以供用户明确确认。

## F-005 — 信心胁迫过于宽松

- 严重性：中等
- 证据：`Number(item.confidence)` 在 `knowledgeExtractionService.js:131-133`。
- 影响：缺失/空/null/字符串置信度可能变为零，而不是未通过结构化输出验证。
- 建议：要求 `typeof value === 'number' && Number.isFinite(value)`。

## F-006 — 证据端点使用无界中间检索

- 严重性：中等
- 证据：`knowledgeExtractionService.js:334-338` 过滤了 JavaScript 中的所有课程证据。
- 影响：成本随着整个证据表的增长而增加，而不是单个候选。
- 建议：添加一个由 `user_id` 和 `candidate_id` 限制且有边界限制的模型查询。

## F-007 — 审查/API 覆盖差距

- 严重性：中等
- 证据：`backend/test/knowledgeExtraction.test.js:49-167`的后端测试未包括拒绝或路由级别的授权测试；前端测试未覆盖拒绝/证据/编辑。
- 影响：生命周期和授权回归可能会通过当前测试。
- 建议：增加路由集成测试以及拒绝/证据/编辑的UI测试。

## F-008 — 忽略提供者确定性参数

- 严重性：低
- 证据：`knowledgeExtractionProvider.js:43-47` 通过了 `temperature`，但 `providers/openaiCompatible.js` 只序列化模型/消息/最大令牌。
- 影响：比暗示的确定性低；没有正确性/安全性故障。
- 建议：要么明确转发温度参数，要么删除未使用的参数。

## F-009 — 提取表缺乏聚焦索引

- 严重性：低
- 证据：新表有主键/外键，但在 `(user_id, status)`、`(document_id, version)` 或 `candidate_id` 上没有索引。
- 影响：随着数据增加，审查/列表/证据查询可能会扫描更多行。
- 建议：在 F-006 修复证据查询结构后添加针对性的索引。

## F-010 — 浏览器预览已有 ShellBootstrap 404

- 严重性：低
- 证据：预览请求 `http://127.0.0.1:4173/js/shellBootstrap.js` 并返回 404；源文件存在，但未复制到 `dist/js`。
- 影响：预览期间控制台不干净。这是预先存在的问题，并非由第25阶段引入。
- 建议：在 build/MPA 稳定化下记录；不要混入第25阶段冻结。
